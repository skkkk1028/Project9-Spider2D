# 二维程序化蜘蛛模拟器：架构与实施计划

## 1. 已确认事实、设计决策与边界

### 已确认

- 技术栈限定为 Python 3.11+、Pygame 和标准库。
- 模拟必须基于 delta time，逻辑与绘制分离。
- 八条腿均使用几何和 IK 计算，不使用图片、逐腿固定帧动画或伪造关节轨迹。
- 第一版以算法可解释、易观察和可测试为优先目标。

### 本计划采用的设计决策

- 使用俯视二维视图。
- 统一使用 `pygame.Vector2`，不引入 NumPy。
- 身体局部坐标约定：`+X` 向前，`+Y` 向身体右侧。
- 世界坐标沿用 Pygame：`+X` 向屏幕右，`+Y` 向屏幕下。
- 当身体朝向角为 0 时，身体前方向屏幕右；正角度在屏幕上表现为顺时针旋转。
- 腿编号为 `L0..L3`、`R0..R3`，0 为最前排，3 为最后排。
- 膝关节和足端 IK 在世界坐标中求解；安装点、默认落脚点和合法区先在身体局部坐标定义，再转换到世界坐标。
- 步态初版采用四相位对角双腿组，任意时刻最多两腿摆动，且同侧最多一腿摆动。

### 无法由纯二维俯视模拟完整验证的内容

- “抬脚高度”没有屏幕平面内的真实空间维度。第一版保存独立的 `lift` 标量（0 到 1），只用于步态状态、颜色、足端大小和阴影偏移；XY IK 不把它当作第三维坐标。
- 因而本项目能验证何时迈步、XY 落脚路径和腿部平面 IK，但不能验证未来 3D 项目的垂直摆腿 IK、离地间隙或地形接触。

## 3. 核心类型与职责

### 配置对象

使用若干 `@dataclass(frozen=True)`，由顶层 `SimulationConfig` 聚合：

- `WindowConfig`：分辨率、目标 FPS、背景色。
- `TimingConfig`：最大可接受帧时长、最大子步时长、时间缩放。
- `BodyConfig`：尺寸、最大速度、加速度、减速度、位置响应、旋转响应和鼠标死区。
- `LegConfig`：上段/下段长度、最小/最大可用伸展率、膝盖偏好、身体安全边距。
- `LegMount`：腿 ID、侧别、排号、髋点局部位置、默认足端局部位置、行进通道。
- `GaitConfig`：触发阈值、紧急阈值、步时长、抬脚比例、摆动高度、冷却、组顺序、最多活动腿数。
- `PlacementConfig`：活动椭圆、预测时间、最小足端间距、候选偏移和各惩罚权重。
- `DebugConfig`：调试层默认开关和颜色。

配置只保存参数，不保存运行状态。固定的八腿解剖安装信息属于集中配置，不属于“逐腿硬编码动画”。

### `Spider`

- 持有 `BodyState` 与 8 个 `Leg`。
- 根据身体姿态计算髋点的世界位置。
- 提供渲染所需的只读快照。
- 不处理 Pygame 事件，也不直接绘制。

### `Leg`

- 静态定义：ID、侧别、排号、两段长度、髋点局部位置、默认足端局部位置。
- 动态状态：`PLANTED/LIFT/SWING/LOWER`、当前世界足端、起步点、计划落点、进度、`lift`、上次膝位置、冷却计时和紧急度。
- 接收步态控制器的“开始迈步”命令并更新轨迹。
- 不自行决定全局上是否允许迈步。

### `TwoBoneIKSolver`

- 无外部状态的解析求解器。
- 输入髋点、目标足端、两段长度、偏好弯曲向量和可选的上一帧膝位置。
- 输出完整 `IKResult`，包括原始目标、实际可达目标、髋/膝/足端、可达状态、误差和选中的弯曲分支。
- 不管理步态，不修改腿状态，不绘图。

### `GaitController`

- 计算每条腿的迈步需求和紧急度。
- 维护四相位组顺序、活动组、最大并发数、支撑腿数量和冷却。
- 只批准满足安全条件的腿开始迈步。
- 紧急情况可提升优先级，但仍不允许同侧两腿同时摆动。

### `FootPlacementPlanner`

- 根据当前/预测身体姿态生成默认落脚点。
- 把候选点限制在该腿的侧半平面、行进通道、活动椭圆和 IK 可达环内。
- 对候选落点执行足端间距、线段相交、穿越身体和离默认点距离评分。
- 在所有可用候选中选最低代价点；没有安全候选时延期迈步或返回明确的降级结果。

### `Simulation`

- 逻辑层总编排器，是每个固定/受限子步的唯一入口。
- 更新输入目标、身体、默认足点、步态、足端轨迹和 IK。
- 生成不可变或只读 `SimulationSnapshot` 给渲染器。

### `Renderer`

- 只读取快照。
- 绘制身体、腿、足端和调试层。
- 不改变任何仿真状态。

## 4. 每帧数据流

```text
Pygame 事件/鼠标
       │
       ▼
InputState ──► App 计算 raw_dt、暂停和时间缩放
       │
       ▼
将 raw_dt 拆为若干不超过 max_substep 的仿真子步
       │
       ▼
Simulation.update(dt)
  1. 身体速度与位置平滑追踪目标
  2. 由有效速度更新身体朝向
  3. 计算 8 个髋点和当前/预测默认落脚点
  4. 计算各腿误差、活动区越界和伸展紧急度
  5. GaitController 审批本子步允许起步的腿
  6. 更新 LIFT/SWING/LOWER 轨迹与 PLANTED 锁地状态
  7. 为每条腿执行解析 IK
  8. 更新诊断计数并生成快照
       │
       ▼
Renderer.draw(snapshot) ──► pygame.display.flip()
```

`raw_dt` 应限制在例如 50 ms 以内，避免窗口拖动或断点恢复后一步跨过整个状态机；再拆成不超过约 8.3 ms 的子步。该方案仍由真实 delta time 驱动，同时改善大帧间隔下的稳定性。

## 5. 坐标系与转换

设身体世界位置为 `C`，朝向为 `θ`：

```text
forward = (cos θ, sin θ)
right   = (-sin θ, cos θ)
world(local_x, local_y) = C + forward * local_x + right * local_y
local(world_point)：
    delta = world_point - C
    local_x = dot(delta, forward)
    local_y = dot(delta, right)
```

约定：

- 左腿的局部 `y < 0`，右腿的局部 `y > 0`。
- 每条腿的“腿局部坐标”复用身体的轴向，但原点放在髋点；因此无需额外维护 8 个旋转角。
- 工作空间判定在身体局部坐标完成，IK 在世界坐标完成。
- 预测落脚点使用预测身体姿态；已着地足端在摆动前始终保持世界坐标不变。
- 角度差必须使用归一化到 `[-π, π]` 的最短角，避免越过 `±π` 时反向旋转。

## 6. 八腿默认锚点与落脚点

不把像素散落在逻辑中，而是由身体半长 `HL`、半宽 `HW` 和比例生成：

```text
row_x_ratio = [+0.72, +0.24, -0.24, -0.72]
side_sign   = -1（L）或 +1（R）

hip_local = (
    HL * row_x_ratio[row],
    side_sign * HW * hip_lateral_ratio
)

default_foot_local = (
    hip_local.x + HL * row_x_ratio[row] * longitudinal_splay,
    side_sign * (HW + stance_width)
)
```

这使前腿自然偏前、后腿自然偏后，中间腿较平。每条腿还拥有一个局部活动椭圆和纵向“通道”：

- 椭圆中心为 `default_foot_local`。
- 椭圆长短轴来自统一配置，可按前/中/后排使用小幅倍率。
- 通道边界由相邻默认足点纵向中点生成，防止同侧足端顺序颠倒。
- 合法点必须满足 `side_sign * local_y >= HW + body_clearance`。

初始足端直接放在当前身体姿态对应的默认世界落脚点，所有腿初始为 `PLANTED`；初始化时不得触发八腿一起“补步”。

## 7. Two-Bone IK

### 输入

- `hip_world: Vector2`
- `target_world: Vector2`
- `upper_length: float`
- `lower_length: float`
- `bend_hint_world: Vector2`
- `previous_knee_world: Vector2 | None`

### 解析过程

令 `v = target - hip`，`d = |v|`。把有效距离夹到：

```text
d_min = abs(L1 - L2) + epsilon
d_max = L1 + L2 - epsilon
d_used = clamp(d, d_min, d_max)
u = normalized(v)              # d≈0 时使用 bend_hint 的垂直方向作为稳定后备
p = perpendicular(u)
a = (L1² - L2² + d_used²) / (2 * d_used)
h = sqrt(max(L1² - a², 0))
knee_candidate_± = hip + u*a ± p*h
```

两个候选都满足骨长。选择时按以下顺序评分：

1. 膝盖位于身体外侧/符合该腿 `bend_hint`。
2. 与上一帧膝位置接近，避免数值扰动造成翻膝。
3. 不进入身体排斥椭圆。

### 输出

`IKResult` 至少包含：

- `hip`, `knee`, `foot`
- `requested_target`, `solved_target`
- `reach_state`：`REACHABLE/TOO_FAR/TOO_CLOSE/DEGENERATE`
- `target_error`
- `bend_branch`

### 不可达目标

- 太远：沿髋到目标方向夹到 `d_max`。
- 太近：沿稳定方向夹到 `d_min`。
- 与髋重合：使用上一帧方向；没有历史时使用该腿默认外向轴。
- 始终对平方根做 `max(value, 0)`，防止浮点误差产生 NaN。
- 调试层同时显示请求目标和实际求解目标；不能静默隐藏不可达状态。

## 8. 迈步判定

对每条 `PLANTED` 腿计算：

- `position_error`：锁定足端与当前默认世界足点的距离。
- `predicted_error`：锁定足端与预测身体姿态下默认足点的距离。
- `workspace_violation`：把锁定足端转回当前身体局部坐标后是否离开活动椭圆、侧半平面或纵向通道。
- `extension_ratio`：当前髋到足端距离除以最大可达长度。
- `cooldown_ready`：落地后是否经过最小冷却时间。

普通起步条件：

```text
cooldown_ready
AND (
    position_error > step_trigger_distance
    OR workspace_violation
    OR extension_ratio > soft_extension_limit
)
```

紧急条件由更高的误差阈值或 `extension_ratio > hard_extension_limit` 触发。阈值要有滞回：开始阈值高于落地后允许误差，避免腿在临界值附近连续抖动。

计划落点不是当前默认点，而是短时预测身体姿态下的默认点，再交给落脚规划器约束与评分。预测时间应被限制，防止鼠标瞬移导致过度超前。

## 9. 八腿分组与调度

首版使用以下四组（每组一左一右、排号相差 2）：

```text
G0 = [L0, R2]
G1 = [R0, L2]
G2 = [L1, R3]
G3 = [R1, L3]
```

核心不变量：

- `active_leg_count <= 2`
- 同侧活动腿数 `<= 1`
- 同组两腿不是同排或相邻排
- 至少 6 条腿保持支撑状态
- 新组只能在当前组所有已起步腿落地后进入

组内不是无条件两腿齐步：只有达到触发条件的成员起步；若另一成员在一个很短的组等待窗口内也需要迈步，可加入本组，否则跳过。组按轮转顺序公平调度，紧急腿可以请求提前，但必须继续满足并发和同侧约束。

严格“一次只动一腿”更安全却不能充分验证协调步态；交替四足组会让同侧两腿同时摆动，违反本项目的保守约束。因此四相对角双腿组是两者之间的初版折中。

## 10. 足端抬起、摆动与落下

单步记录 `start_world`、`landing_world`、`elapsed`、`duration` 和 `lift`，按归一化进度分三段：

- `LIFT`（约 0%–20%）：XY 保持起点，`lift` 用 smoothstep 从 0 到 1。
- `SWING`（约 20%–80%）：XY 沿二次 Bézier 曲线从起点移动到落点，`lift` 保持高位或使用平缓拱形。
- `LOWER`（约 80%–100%）：XY 固定在落点，`lift` 用 smoothstep 从 1 到 0。

摆动控制点位于起终点中间，并向该腿身体外侧和自己的纵向通道中心偏移，降低路径扫过身体或邻腿的概率。所有插值只由通用轨迹函数和配置参数产生，不为某条腿保存固定关键帧。

状态转换时必须精确钳制端点：

- 起步瞬间不跳变。
- 落地时 `foot_world == landing_world`。
- 落地后足端世界位置保持锁定，直到下一次迈步。

## 11. 防跨中线与降低重合

采用“硬约束 + 软评分”：

### 硬约束

- 候选足点必须留在本侧安全半平面。
- 候选足点必须位于该腿活动椭圆、纵向通道和 IK 可达环的交集内。
- 摆动 Bézier 控制点也必须投影回本侧安全区域。
- IK 两个膝候选优先排除进入身体椭圆或明显位于错误一侧者。

### 软评分

对中心候选及其沿通道的若干偏移候选评分：

```text
cost =
    默认落点偏差
  + 邻近足端距离不足惩罚
  + 与邻腿骨段相交惩罚
  + 靠近身体边界惩罚
  + 接近 IK 极限惩罚
  + 相对上一落点变化过大惩罚
```

首版只检测二维线段相交和最小距离，不做连续碰撞求解。它能显著降低明显重合，但不能保证在所有快速转向和极端目标下绝不穿模。

## 13. 可独立运行的里程碑与验收标准

### M1：应用骨架与时间系统

运行：主入口显示空窗口和 HUD。

验收：

- Python 3.11+ 可启动，只有 Pygame 运行依赖。
- resize/退出/暂停/单步工作。
- 仿真收到秒为单位的 dt，长帧被限制并拆分子步。
- 配置、逻辑、绘制不在同一文件。

### M2：身体运动与坐标变换

运行：`body_demo`，身体追踪鼠标。

验收：

- 身体不瞬移，速度和加速度受限。
- 有效移动时平滑朝向速度方向；停止时保持最后朝向。
- 局部点到世界再转回局部，误差低于浮点容差。
- 同一脚本轨迹在 30/60/144 FPS 下最终位置和朝向近似一致。

### M3：单腿 IK

运行：`ik_demo`，髋固定，鼠标控制足端。

验收：

- 可达目标下两段长度误差小于 `1e-4` 或像素级显示容差。
- 太远、太近、目标重合均无 NaN/崩溃，并显示状态。
- 围绕髋点连续移动目标时膝盖不无故翻侧。
- 可切换弯曲提示验证两解析分支。

### M4：静态八腿装配

运行：`gait_demo` 的静态模式。

验收：

- 恰好 8 条腿，每腿两骨段和足端。
- 左右安装点及默认足点镜像；前后顺序正确。
- 身体平移/旋转时未锁地模式下局部结构保持一致。
- 初始姿态没有跨中线和不可达目标。

### M5：足端锁地与单腿步进

运行：一次只允许一腿迈步。

验收：

- `PLANTED` 足端在身体移动时世界坐标不漂移。
- 超阈值腿完成 LIFT→SWING→LOWER→PLANTED。
- 起步和落地无位置跳变，步时长不依赖 FPS。
- 任意时刻活动腿数不超过 1。

### M6：四相分组步态

运行：完整四组轮转，但尚未启用高级候选评分。

验收：

- 任意时刻活动腿不超过 2、同侧不超过 1、支撑腿不少于 6。
- 不相邻对角组按公平顺序获得迈步机会，无长期饥饿。
- 静止时不持续原地踏步；低速和转向时不会八腿同时触发。
- 鼠标沿圆形、折线和突然跳点移动时状态机不锁死。

### M7：落脚约束与重合降低

运行：显示活动区、候选点和相交诊断。

验收：

- 落脚点不越过本侧安全边界，不打乱同侧前后通道顺序。
- 常规轨迹中足端最小间距违规和骨段交叉能被检测、记录并显著减少。
- 没有合法候选时系统延期或明确降级，不静默生成非法点。
- 快速旋转时弯膝分支保持连续，异常情况有调试标记。

### M8：回归、调参与交付

运行：主入口和全部自动测试。

验收：

- 所有数学、IK、轨迹和步态不变量测试通过。
- 30/60/144 FPS 脚本回放结果在约定容差内。
- 连续运行至少 10 分钟无 NaN、异常和持续不可达腿。
- README 记录安装、运行、按键、已知限制和参数说明。

## 14. 主要风险、常见错误和测试方法

| 风险/错误 | 原因 | 对策与测试 |
|---|---|---|
| FPS 不同导致步长不同 | 把“每帧增量”当速度 | 所有速度乘 dt；对同一输入做 30/60/144 FPS 回放 |
| 长帧穿过状态 | dt 突增 | 限制 raw_dt、子步更新；注入 100–500 ms 长帧测试 |
| 身体转向时足端漂移 | 锁地点错误保存在局部坐标 | `PLANTED` 保存世界坐标；旋转身体做回归测试 |
| 膝盖突然翻转 | 只按叉积符号，目标接近共线 | 弯曲提示、上一膝连续性和分支滞回；目标绕圈测试 |
| IK 出现 NaN | 余弦/平方根浮点越界或距离为零 | 夹取输入、epsilon、`max(…,0)`；随机属性测试 |
| 所有腿一起触发 | 每腿独立立即起步 | 统一调度器审批；每帧断言并发和同侧不变量 |
| 腿长期得不到迈步 | 固定组等待或紧急腿反复抢占 | 轮转公平性、等待年龄加权；长时间脚本统计每腿步数 |
| 落点跨中线 | 只限制默认点，未限制预测/轨迹 | 对落点和 Bézier 控制点都投影；每子步检查侧半平面 |
| 相邻腿重合 | 只取单一默认点 | 多候选评分、通道约束、线段相交惩罚；记录交叉率 |
| 身体跑得比腿快 | 鼠标可瞬移而步态吞吐有限 | 限制身体速度/加速度，紧急阈值；极端时允许追踪滞后 |
| 快速转向导致无可行落点 | 预测姿态与腿可达区冲突 | 限制预测时间，候选降级/延期，显示不可行原因 |
| 暂停后恢复跳变 | 时钟累计暂停时间 | 恢复时丢弃首个 raw_dt；自动化暂停/恢复测试 |
| 绘制逻辑改变状态 | Renderer 持有可变模型 | 只传快照；测试连续绘制不改变状态哈希 |

### 推荐自动化测试

- 变换往返测试和角度边界测试。
- IK 边界值与随机可达目标属性测试。
- 轨迹起点、终点、连续性、时长和 `lift` 范围测试。
- 步态不变量逐帧断言。
- 脚本化鼠标路径：静止、直线、圆、八字、急转、瞬移。
- 诊断统计：每腿步数、不可达帧数、交叉次数、最小足端间距、最大锁地漂移。

## 15. 进入编码前的参数基线

以下只作为第一轮调参起点，最终全部放入配置：

- 窗口约 `1200×800`，目标绘制帧率 120。
- 身体半长约 30 px、半宽约 18 px。
- 两骨段约 38 px 与 42 px。
- 默认侧向站宽约 48–58 px。
- 单步时长约 0.25–0.35 s，抬起/落下各占约 20%。
- 普通迈步误差约 18–25 px，紧急误差约为普通阈值的 1.5–2 倍。
- 身体最大速度必须根据“单步距离 ÷ 步时长”约束，不能独立随意调大。

这些数值目前是合理起点，不是已验证事实；M2–M7 中应通过可视化与统计逐项校准。

## 16. 编码顺序

1. 先实现配置、数学工具和快照类型。
2. 完成 M1/M2 并写变换与 dt 测试。
3. 把 IK 做成独立纯函数，完成 M3 后才接入八腿。
4. 完成静态装配与初始化不变量。
5. 先实现一次一腿的锁地和状态机，再升级到四相调度。
6. 最后加入候选评分和重合降低，避免在基础状态机未稳定前混入复杂约束。
7. 每个里程碑保留独立 demo 或命令行模式，后续 3D 迁移时可单独对照算法。
